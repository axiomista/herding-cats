## Spec ambiguities and the choice made

1. **Matching runs once per cycle across the folder, not per file.** Step 7 matches "the file's commitments" against every task, but orphans and misfiled tasks can only be judged with every file's commitments in view (T7 sits on the brainstorm but belongs to the memo). Each cycle scans only the files it is given, keeps each file's extracted commitments in memory, then matches all known commitments against all folder tasks. Orphans are reported only for tasks on files scanned in this process, so a restart never turns every task into an orphan.
2. **Restatements across files merge.** Step 6 deduplicates within a file. The answer key counts C01 once although sync01 restates it, so the same rule (same owner, similarity of 80 or more) also merges across files, keeping the earliest document's commitment and recording the others as `mentions`. A task on a file with a mention is not misfiled.
3. **Edit check (step 8) is the orphan rule.** Rescanning a file replaces its commitments in memory; a task on it whose commitment is gone is then unpaired, so it becomes a low-certainty orphan.
4. **Status changes.** A `status_change` with `cancelled` or `completed` updates the best commitment whose text scores 85 or more against `refers_to`. With no such commitment in memory, it becomes a commitment of its own (owner missing, so low certainty) that can still pair with the open task.
5. **Completed tasks.** A pair with a completed task is `matched`; conflicts on a closed task are not reported. Unpaired completed tasks are not orphans.
6. **Certainty of matched findings.** The bucket check passes for `matched` (nothing to write), so matched cards are high certainty and do not crowd the top of the page.
7. **Pairing check.** Applies only when a task is paired. "No other candidate within 10 points" passes when the best rival on either side of the pair scores at least 10 below the pair. Untracked findings have no pairing check; their best task scored below 60 by definition.
8. **Scan marker format.** `hcScannedVersion` is `<file_version id>@<prompt version>` (for example `2810308355440@v1`), so a new prompt version rescans every file without a separate field.
9. **Versions are Box `file_version` IDs**, which change on every upload. The audit entry's "version" is that ID.
10. **Dry run keeps scan markers in memory.** Metadata is written in apply mode only, as the spec says, but a dry-run sweep still skips files this process already scanned, so repeated sweeps cost no AI units. In apply mode, metadata is written for every file whose marker in Box is missing or stale, including files scanned earlier in dry run.
11. **Metadata write.** One write per file, after every task, comment and audit write of the cycle. A new version or a fresh extraction writes all `hc*` fields. Otherwise a file is written only when its open-finding count changed or the cycle wrote a task, comment or HELD entry for it, and then only `hcLastChecked`, `hcOpenFindings` and `hcLastChange`; a sweep that changed nothing writes no metadata, so `hcLastChecked` is the last check that changed something. `hcOpenFindings` is a count; `hcLastChange` is the trigger of the cycle that wrote it. A failed write is recorded per file in the page's errors and retried next cycle.
12. **HELD entries** are logged once per finding fingerprint per process, so each sweep does not repeat them.
13. **Audit trigger labels**: `webhook`, `sweep`, `full-scan`, `click`. Times are Pacific (`PT`).
14. **Audit fields not in the sample.** The `finding` line follows the sample (`bucket: action, due date`); the owner appears in the `change` line. Orphan evidence is written as `none (task <id> on file <id>)`.
15. **Comment wording** starts with "Herding Cats:" and ends with `fingerprint: <fingerprint>`.
16. **Dates.** Only explicit dates resolve ("October 23", "Oct 23, 2026", ISO). A month and day before the document date roll to the next year. Relative dates ("next Friday") are flagged and never guessed.
17. **Owners.** "I", "me" or "myself" in an email thread resolve to the sender of the message containing the evidence. External people (`external: true`) and people with no Box user are flagged.
18. **Unsupported types.** Supported extensions: txt, md, pdf, doc, docx, rtf, odt, html, htm, ppt, pptx, xls, xlsx.
19. **Terraform supports Express Mode.** `aws_ecs_express_gateway_service` exists in hashicorp/aws 6.69.1, so the Fargate-behind-an-ALB fallback is not needed. Scaling is pinned to min 1 / max 1.
20. **One KMS key for the secret.** The `herding-cats/env` secret uses a dedicated KMS key with rotation, following AWS secret best practices; the execution role may decrypt only through Secrets Manager.
21. **Deploy role trust** is limited to the repository's `production` GitHub environment, which `deploy.yml` uses.
22. **Docker image contents.** `dist/`, production `node_modules`, `prompts/`, `config/` and `seed/answer_key.json` (for `POST /api/score`). Test fixtures and seed docs are left out, so `FAKE_BOX=1` is a local mode only.
23. **Past due dates.** Box rejects a task due date in the past with a 400 (seen live while seeding). `createTask` then creates the task without a due date, and the audit `change` line says so; the outcome stays `ok`.
24. **Restatements that only the task connects.** Found on the first live eval: the model wrote the sync01 restatement as "book the Great Hall", which scores 59 against C01 (below the dedupe threshold) but 100 against T1. An unpaired open commitment whose best task scores 85 or more and is already paired with the same owner's commitment now becomes a mention of that commitment, not an untracked finding.
25. **Untracked needs a clean miss.** An untracked finding is high certainty only if no task scored 60 or more; otherwise its pairing check fails and it is held. This keeps the audit line "no task scored above 60" true and stops a near-duplicate from becoming an automatic task.
26. **Express 5** is what `npm install express` resolves to today; the spec names no version.
27. **AI call count is per process.** The spec's status shows "AI calls this month", but the count lives in memory and resets on restart, and the spec rules out a store for it. The page labels it "AI calls since start"; Box's admin console has the monthly figure.
28. **Corpus dates shifted forward.** By the demo (2026-10-17) most seed due dates had passed, and Box rejects past due dates, so planted and created tasks lost them. Document dates moved 13 days, which also makes every written weekday correct for 2026; due dates moved 21 days, so the earliest is 2026-10-22 and each still falls after its document. The meeting date in Weekly Sync 02's "NEXT SYNC" line moved with the document dates. The four dated seed files were renamed to match. The audit test keeps the spec's sample entry as written.
29. **A cancellation counts whatever the model calls it.** Any extracted item with a new status of cancelled or completed is treated as a status change, because the live model sometimes labels "The Human Acclimation Lab box order is cancelled." a decision. A status change is scored against each commitment's text and its evidence sentence. It applies at 85 or more, or at 60 or more when it beats every other commitment by the rival gap (10); below 85 the finding's status check fails, so it is held for a person rather than written automatically. On the live corpus the box order's cancellation scores 83 against C05's evidence and 48 at most against anything else.
30. **Owner conflicts on other people's tasks are never written automatically.** Someone assigned that task, and may know something the document does not, so the finding is shown for review and its comment is posted only on a click. An owner conflict on a task Herding Cats created is still written in apply mode. The process remembers the IDs of tasks it created; after a restart it knows none, so every owner conflict waits for a person until it creates more.
31. **Sweeps can be turned off (new).** `SWEEPS_ENABLED=false` skips the startup sweep and the timed sweep, to stay inside the Box AI and API budget; webhooks and Scan now still run. In dry run the page starts empty after every restart until one of them runs. On AWS it is a plain environment variable set from the Terraform variable `sweeps_enabled` (default `false`), not a key in the secret, so a merge turns it on or off without a console edit.
32. **Images and scans go through OCR (new).** The inventory takes `.png`, `.jpg`, `.jpeg`, `.tif`, `.tiff` and `.webp`. Box has no text layer for an image, and for a scanned PDF its `extracted_text` is empty; `/ai/extract` returns nothing for a scan (it has no OCR), but `/ai/extract_structured` transcribes it (all 7 pages of the corpus's long scan). So when a PDF or image has no text, one structured call transcribes it, extraction is sent that transcription as the item's `content`, and the evidence check runs against it. The quote is then checked against Box AI's own reading rather than the file, so those commitments are flagged `evidence from OCR`, the evidence check fails and they are held at low certainty. A PDF with a text layer is never sent to OCR, so a scanned page inside an otherwise digital PDF is still not read. `.vtt` stays out: Box has its text, but Box AI rejects the extension with a 400 even when the text is passed as content.
